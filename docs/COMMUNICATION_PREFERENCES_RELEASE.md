Status: granted / not_provided / withdrawn; no row = "not recorded". Records adult, destination (number/email, mobile vs home/work), date/time, wording version COMMS-1.0 (NL-1.0 kept), language, source, later withdrawals. Reuses the existing register tables. Changes to `capture_apply`, `eligible()`, `critical_prepare_p4`; new service-role RPCs `channel_consents_p5`, `channel_consent_set_p5`, `sms_recipients_p5`, `sms_stop_p5`. No feature-flag, cron or network statements.

## Behavior
* An unchecked box or unanswered newsletter is never consent and never overwrites an existing grant. A grant in an application cannot silently reinstate a withdrawal (logged as `grant_ignored_withdrawn`; the Director re-authorizes with evidence in the communications admin tool).
* Essential safety messages are never excluded for unknown consent or a declined newsletter; only an explicit email withdrawal removes a family from the email list, and that family moves to the critical phone follow-up list.
* Future SMS: data model only (mobile vs landline/work, STOP handling, independent of email). No provider, number, campaign or sending code.

* "Mobile" is taken from the cell-phone field; real line-type lookup belongs to the future SMS provider.
* A new granted number does not revoke older granted numbers.
* SMS/consent wording needs legal review before any texting is enabled.
